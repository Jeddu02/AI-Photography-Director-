# Shot Director v0.2

For the v0.3 selection, crop-protection, zoom-threshold, readiness and animation changes, see [SUBJECT_DIRECTOR.md](SUBJECT_DIRECTOR.md). That contract takes precedence over overlapping v0.2 details below.

This is a local photography framing heuristic. It proposes a crop of the current preview and guides the user toward it. It does not see outside the displayed image, know which place is best to visit, control another application's zoom/shutter, or understand beauty.

## Pipeline and contracts

The existing bounded one-frame capture/inference pipeline provides a 64×64 RGB scene map, detected boxes, exposure and frame difference. No extra SDK/model/network dependency was added. Numeric scene maps remain transient. The previous map and one selected goal are retained in memory until reset for image registration, never written to disk by the app.

1. Filter detections by the sensitivity threshold (default .55). Auto favors people, otherwise a large area×confidence object; multiple people form one protected group. Portrait favors people/faces. Group uses the union of people/faces. Food uses supported food classes. Landscape uses scene detail without assigning a semantic label. Portrait/Group cannot recommend capture without detected people/faces.
2. Evaluate same-aspect-ratio crops with normalized width/height 1, .86, .72 or .58. Each tighter crop tries a 6×6 position lattice. Values are normalized within the manually calibrated camera-preview rectangle. These are content-ranked proposals, not random tips.
3. Compute luminance (Rec.709 weights), gradient detail, RGB contrast against scene mean and local luminance contrast. Visual interest = .46×edge + .34×color contrast + .20×local contrast, clamped 0–1. A scene without a subject needs luminance standard deviation >=.035 and average interest >=.025 before proposing a frame.
4. Score crops: .35×interest density + .12×normalized edge detail + .13×exposure suitability + .04×interest retention + .025×crop width − .10×border edge density. For a detected subject, add .90×subject-fill suitability + .22×selected horizontal-placement suitability. Desired subject heights: Portrait .70; Group/Food .64; others .58. Crops must retain >=97% of the selected box/group union; tighter crops require .035 frame-width margin. Scene-only crops add .28×sqrt(interest density) + .13×interest-centroid balance. These weights are engineering heuristics, not calibrated confidence in photographic quality.
5. Prefer a full view if the best crop's score improves it by less than .005. Keep up to five diverse choices with intersection-over-union <=.68. “Find another shot” advances through the current scene's proposals. No subject name is invented for scenery.
6. Lock one goal rather than continually proposing tighter crops. Follow same-label subject geometry or bounded RGB/luminance image registration between consecutive maps. Registration searches relative scale .6–1.45 and center offsets ±.12, then refines; mean residual >.105 rejects the match. Two failed matches or an implausible transformed frame discard the goal. A subject of the same class can be confused with another; moving subjects, lens switches, parallax, mirrored/rotated views, repeated texture, overlays and large camera movement can break registration. This is approximate frame tracking, not SLAM/depth or camera pose estimation.
7. Ask to center the highlighted area if its center differs from preview center by >.055 on either axis. Arrow vector = highlighted center − preview center, consistently in displayed image coordinates. It describes the area to aim at; it does not infer a safe physical step. Relative zoom = 1/goal width, displayed within .5–2×; cue zoom if >1.13 or goal width >1.13. “1.2× from this view” is a multiplier from what is currently shown, not an absolute camera zoom setting. The camera's actual lens/zoom state is unknown.
8. Subject touching within .018 of a frame edge immediately requests zoom out and clears the old target. Mean brightness <.13 or clipped highlights >.42 blocks capture. Frame difference >.14 postpones initial proposal; >.055 blocks readiness. Reported eye-open estimate <.35 and Portrait/Group absolute face yaw >32° block readiness. Missing eye/yaw data is unknown, not proof of a clear face.
9. An aligned frame meeting supported checks remains qualifying for >=1300 ms, plus 550 ms instruction hysteresis, before “Frame ready — take the shot!” Red warnings and loss of readiness revoke it immediately. Observation gaps >2000 ms reset the sequence. Scenery may now qualify geometrically in Landscape; this is not semantic moment recognition. Manual Composition never claims AI readiness. Readiness does not guarantee an attractive image or unobserved subject visibility.

## Visual behavior

One thin crop outline, corner brackets, an aim reticle and a short cue replace the default full grid. Zoom cues appear after aim/alongside it as appropriate. The grid remains optional. Automatic v0.1 settings receive a one-time grid-off migration, preserving mode, preview calibration, opacity, threshold and performance preset.

Position/size interpolate exponentially with a 180 ms time constant; each draw uses elapsed display time with an 80 ms cap. Color/progress ease over 140 ms; a subtle 1400 ms pulse draws attention without flashing. Balanced/High Responsiveness request display-synchronized redraws; Battery Saver requests ~33 ms intervals. This decouples animation from AI observation cadence (1000/450/220 ms presets); it is not a measured FPS guarantee. Paused, unavailable, compact and manual states do not run the shot-animation loop. Models still execute asynchronously with existing backpressure/thermal slowdown.

## Evidence and limits

Pure Kotlin tests exercise content-dependent framing, bounds/aspect, group retention, subject zoom, relative image registration, transforms, locked goals, alternative choice, readiness, arrow signs, portrait failure, dark failure and interpolation. Flutter tests cover state/channel/settings and narrow-screen flows. A private numeric probe of the user's supplied stock-camera screenshot selected a crop x=.112–.972, y=.140–1.000 inside the image, and indicated downward aiming followed by approximately 1.2× relative zoom. The actual photo/derived pixel fixture is excluded from the distributable source. This probe tests the planner, not live capture or aesthetic quality.

v0.1 overlay operation was reported by the user and visible in their screenshot. No physical Android device/emulator was available here for v0.2. Live zoom-following, indicator smoothness, camera touch behavior, rotation, interruption and prolonged operation require testing on the phone. Protected camera previews remain incompatible with automatic analysis; use the separate manual-guide session.

The older rule table in COMPOSITION_RULES.md describes the legacy no-scene-map fallback. The scene-map path in this document takes precedence for automatic modes in v0.2. The previous separate headroom/looking-room/background/horizon messages are not all combined into this new shot-goal score; no expanded semantic capability is claimed.
